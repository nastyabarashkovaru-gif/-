# HUSH — visual-first implementation specification

Build a Telegram Mini App using React, TypeScript, Vite, Tailwind CSS, Lucide icons, Motion. Implement all screens according to `screens/*.png` and `design-reference.html`. Screenshots are visual references, not a pixel-perfect export of the original chat mockups; use their approved copy, layout hierarchy, dark premium style. Mobile-first, 390×844 reference, responsive heights, safe areas. No bottom navigation. Black #000, purple #A855F7 / #8B5CF6, green #4ADE80, dark panels #111114, Inter. Main white CTAs have animated iridescent purple outline (respect reduced motion). Avoid gradients/glows except subtle animated CTA border. No fake statistics or fabricated respondent answers in production; demo seed must be clearly labeled.

## Screens
01 welcome: purple rotating question every 3s; CTA → 02.
02 select exactly five from 21+ questions, five purple progress segments; custom questions premium only. CTA → 03.
03 ready: copy full personalized share message; native Telegram share; results link → 04/05.
04 waiting: 0–4 unique completed respondents, 5-segment progress, privacy explanation, share again. At fifth completion Telegram bot notification; show results.
05 results: horizontal swipe carousel per respondent; first (most substantive) respondent all five responses, other respondents two visible and three locked; lock CTA → 06. Static create-another CTA, premium gated. 50/100 respondents scalable, preserve card position.
06 premium: monthly 299 RUB, quarterly 499 RUB, annual 1499 RUB selected and visually dominant; savings 44% and 58% vs monthly; benefits, green check on identity reveal; auto-renew cancellation copy exactly 'Отменить подписку можно в любой момент в настройках профиля'. **PAYMENT BUTTONS ARE VISUAL PLACEHOLDERS ONLY. DO NOT CONNECT A PROVIDER, CREATE CHARGES, OR GRANT ENTITLEMENTS ON CLICK.** Show a non-transactional 'Оплата пока недоступна' hint if tapped. No API keys or fake successful payment. Verify Telegram Stars requirements before any production payment integration; do not assume ruble payment can be collected inside Telegram for digital goods.
07 reveal: show button for every respondent; check consent BEFORE any charge. If explicit consent true and valid entitlement, show only permitted Telegram identity fields; otherwise modal 'К сожалению, этот автор пожелал остаться анонимным. Попробуй узнать, кто оставил другие ответы 👀' with button 'Следующий аноним →'. If annual entitlement unlimited consented reveals; monthly/quarterly per-reveal 99 RUB was previously discussed but is pending product confirmation; do not implement actual payments. Avoid leaking respondent identity via API, logs, analytics, or client payload before authorization.
08 answer flow: five full-screen steps, one question each, one textarea placeholder 'Отвечай максимально честно'; next disabled until non-empty, smooth horizontal slide (forward left / backward right) 250–350ms; preserve answers. After fifth → anonymity choice screen 08b: anonymous preselected; alternate explicit opt-in allowing profile to be revealed to questionnaire owner for an additional fee or under annual subscription. Store consent auditable. Only after selection send all five responses atomically.
09 submit success: 'Твои ответы отправлены! 💜' / 'Спасибо за честность!' then viral CTA to create own questionnaire, skip welcome if appropriate.
10 settings: Telegram profile, questionnaire list, subscription status, management and cancellation, support. Mock settings subscription state clearly identified as demo; actual billing controls must not claim cancellation occurred without provider confirmation.

## Backend plan (do not implement unless explicitly requested)
Persist Telegram-authenticated users, questionnaires (owner and exactly five question IDs or custom text), response sets, consent records, subscription entitlements, per-reveal purchases, event idempotency. Validate Telegram initData server-side, prevent self-response and duplicate respondents per questionnaire, implement rate limits, anti-abuse. Unique respondent threshold five, but never claim guaranteed anonymity. The questionnaire owner sees all question text and only permitted answer texts. Do not send locked answer text or unconsented Telegram identity to client. Bot notifies owner at threshold exactly once. Provide terms, privacy policy, opt-in disclosure and compliant billing/cancellation UX.

## Functional QA
Check every CTA, empty/error/loading states, no response fabrication, swipe for many respondents, keyboard/safe area, 5-step progress, annual default, consent/no-consent modal, free vs premium entitlements, 21+ questions, accessible focus, reduced motion. Preserve all copy from HTML references.
