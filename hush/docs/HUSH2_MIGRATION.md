# HUSH 2.0 — план миграции

Принцип: только добавление. Ни одна существующая таблица и строка не удаляется и не меняет смысл.

## Новое в схеме (server/src/db.ts, идемпотентно при старте)
- `users.ask_slug` — постоянный код личной ссылки (`startapp=u_<slug>`), создаётся сервером один раз.
- `users.ref_source`, `users.referred_by` — источник привлечения (start_param первого входа) и кто привёл
  (владелец личной ссылки / вопроса / анкеты). Пишутся только для новых пользователей.
- `users.daily_last_at` — дата (МСК) последнего ежедневного вопроса от hush.
- `inbox` — входящие анонимные вопросы: `kind` user | self | system, ответ, удаление, жалоба.
- `asks`, `ask_answers` — «Задать свой вопрос»: свой вопрос (`startapp=a_<id>`) и анонимные ответы.
- `blocks`, `reports` — блокировки отправителей и жалобы (личность отправителя не раскрывается).

## Старые данные
- Анкеты, ответы, раскрытия, подписки, платежи — без изменений.
- Старые ссылки `startapp=<id анкеты>` открывают прежнюю форму ответов.
- Старые анкеты — в разделе «Мои вопросы» → «Анкеты из прошлой версии» (прежний экран результатов).
- Подписки и автосписания CloudPayments не трогаются; Premium продолжает работать.

## Ссылки
- `u_<slug>` — личная ссылка «задай мне вопрос», `a_<id>` — свой вопрос, `ref_*` — рекламные метки,
  `admin` — статистика, прочее — id старой анкеты.
