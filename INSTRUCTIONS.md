# Инструкция: что нужно сделать, чтобы запустить «100 дней спорта»

Приложение уже написано и лежит в этом репозитории (`backend/` + `frontend/`). Ниже — пошаговый план того, что нужно сделать именно тебе, чтобы оно заработало в Telegram у реальных участников.

---

## 1. Создать Telegram-бота и Mini App

1. Открой в Telegram **@BotFather**.
2. Команда `/newbot` → придумай имя и username бота (например, `100daysport_bot`).
3. BotFather пришлёт **токен бота** — сохрани его, он понадобится в `backend/.env` как `BOT_TOKEN`.
4. Команда `/mybots` → выбери своего бота → **Bot Settings → Menu Button** → укажи ссылку на задеплоенный фронтенд (получишь на шаге 4) и текст кнопки, например «Открыть приложение».
   - Альтернативно можно создать полноценный Mini App через `/newapp` — тогда приложение будет открываться и по прямой ссылке `t.me/<bot>/<appname>`.

---

## 2. Настроить переменные окружения backend

В папке `backend/` скопируй `.env.example` в `.env` и заполни:

| Переменная | Что вписать |
|---|---|
| `BOT_TOKEN` | Токен из BotFather (шаг 1.3) |
| `ADMIN_JWT_SECRET` | Любая случайная длинная строка (для подписи админ-сессий) |
| `ADMIN_LOGIN` / `ADMIN_PASSWORD` | Логин и пароль для входа Насти в админ-панель — **обязательно смени** дефолтные значения |
| `CHALLENGE_DAYS` | 100 (можно не менять) |
| `PRODAMUS_SHOP_URL`, `PRODAMUS_SECRET_KEY` | См. раздел 5 ниже |
| `DEV_MODE` | `true` для локальной разработки, `false` в проде |

---

## 3. Запустить и проверить локально

```bash
cd backend
npm install
npm run dev        # backend на http://localhost:4000

cd frontend
npm install
npm run dev         # frontend на http://localhost:5173
```

Открой `http://localhost:5173` в браузере — вне Telegram появится кнопка «Войти как тестовый пользователь» (это dev-режим для проверки без реального Telegram-аккаунта). Пройди анкету, отметь пару дней в трекере, проверь разделы «Участники» и «Рейтинг».

Админ-панель: `http://localhost:5173/admin/login`.

---

## 4. Задеплоить приложение (чтобы оно открывалось в Telegram)

Telegram Mini App **обязательно должен открываться по HTTPS**-ссылке — localhost не подойдёт для реальных пользователей.

Нужно задеплоить отдельно:

- **Frontend** (`frontend/`, статическая сборка через `npm run build` → папка `dist/`) — подойдёт Vercel, Netlify, Cloudflare Pages или любой статический хостинг.
- **Backend** (`backend/`) — нужен сервер с Node.js и **постоянным диском** (файловым хранилищем), так как:
  - база данных — файл SQLite (`backend/data/app.sqlite`);
  - загруженные фото/видео тренировок хранятся в `backend/src/uploads/`.
  
  Подойдёт Railway, Render (платный план с постоянным диском), VPS с PM2/systemd, или аналогичный сервис. На бесплатных хостингах с эфемерной файловой системой (например, бесплатный Render) файлы и база будут стираться при каждом перезапуске — для продакшена это не годится.

После деплоя backend:
1. Пропиши в переменных окружения хостинга то же самое, что в `.env` (шаг 2), плюс порт, который требует хостинг.
2. Во фронтенде (`frontend/vite.config.ts` использует прокси `/api` только для локальной разработки) — в проде нужно либо разместить frontend и backend на одном домене за общим реверс-прокси (Nginx/Caddy), либо задать в `frontend/src/api/client.ts` полный URL backend вместо относительного `/api` (переменная окружения вида `VITE_API_BASE`).

После деплоя frontend — вернись в BotFather и укажи готовую HTTPS-ссылку в Menu Button (шаг 1.4).

> Рекомендация: используй тот же хостинг/сервер, что уже развёрнут под приложение клуба «90 дней» — это ускорит и упростит деплой, раз инфраструктура уже настроена.

## 5. Подключить приём оплаты через Продамус

Приложение генерирует персональную ссылку на оплату «цены слова» и принимает вебхук об оплате (`backend/src/routes/payments.ts`).

Что нужно сделать тебе:

1. В личном кабинете Продамуса (тот же аккаунт, что уже используется для тарифов клуба) открой **Магазин → Настройки → API** и скопируй:
   - `PRODAMUS_SHOP_URL` — адрес твоей формы оплаты (например, `https://клуб.payform.ru`);
   - `PRODAMUS_SECRET_KEY` — секретный ключ для подписи запросов.
2. Впиши их в `backend/.env`.
3. В настройках вебхуков Продамуса укажи URL:
   `https://<твой-backend-домен>/api/payments/webhook/prodamus`
4. **Важно:** точные названия полей запроса и алгоритм подписи в коде (`backend/src/routes/payments.ts`) реализованы по стандартной схеме Продамуса, но у разных тарифов/версий API могут быть нюансы. Перед запуском на реальных деньгах обязательно:
   - сделай один тестовый платёж на минимальную сумму и проверь, что вебхук доходит и платёж помечается «оплачено» в админ-панели (`/admin/payments`);
   - если что-то не совпадёт — сверь точные названия параметров с документацией/поддержкой Продамуса и поправь функции `buildProdamusLink` и обработчик `/webhook/prodamus`.

## 6. Как работает определение победителя (важно понимать)

Согласно ТЗ, это **не полностью автоматизировано** — и в коде это сделано намеренно так же:

- Приложение автоматически считает только **посещаемость**: галочки по тренировкам с учётом форс-мажора («жизней»). По этому показателю оно определяет, дошёл ли участник до конца формально.
- Реальную победу (кто действительно достиг цели и заберёт призовой фонд) **определяет вручную администратор** — Настя, в админ-панели:
  1. Открой `/admin` → выбери участника → `/admin/users/:id`.
  2. Проверь его анкету, цель, фото и отчёты.
  3. Если участник реально достиг цели — поставь галочку **«Подтвердить как победителя»** и сохрани.
  4. Только после этого в приложении участника появится экран с сообщением о победе и призовом фонде.
- Оплаты «цены слова» от тех, кто не дошёл до конца, можно проверять и вручную помечать оплаченными на странице `/admin/payments` (для спорных случаев, если вебхук Продамуса не сработал).

## 7. Что ещё стоит сделать перед запуском на живых участниках

- [ ] Сменить `ADMIN_LOGIN` / `ADMIN_PASSWORD` на надёжные (не дефолтные).
- [ ] Поставить `DEV_MODE=false` в проде — иначе вход возможен без реальных данных Telegram.
- [ ] Настроить регулярный бэкап файла `backend/data/app.sqlite` и папки `backend/src/uploads` (это единственное хранилище данных участников).
- [ ] Если участников станет много — подумать о переносе фото/видео с локального диска на облачное хранилище (S3-совместимое), это не обязательно для старта, но полезно на масштабе.
- [ ] Проверить лимит загрузки файлов (сейчас 100 МБ на видео) — при необходимости поменять в `backend/src/upload.ts`.
- [ ] Протестировать весь путь одного участника от входа в Telegram до дня 100 на тестовом боте, прежде чем открывать доступ всем.

## Структура на случай, если нужно что-то поправить

```
backend/src/
  db.ts              — схема SQLite
  auth/               — проверка Telegram initData и админ-авторизация
  routes/
    users.ts          — анкета, участники, рестарт челленджа
    progress.ts        — трекер 100 дней, загрузка фото/видео
    rating.ts          — рейтинг и призовой фонд
    payments.ts         — интеграция Продамуса
    finale.ts           — логика финала (день 100)
    admin.ts             — админ-эндпоинты

frontend/src/
  pages/               — экраны приложения (анкета, участники, рейтинг, профиль, прогресс, финал)
  pages/admin/          — админ-панель
  styles/global.css      — тёмная тема, неоновый акцент (переменные в :root)
```
